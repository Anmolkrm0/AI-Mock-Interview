# Database

Schema is defined in `backend/app/models/entities.py` and created by Alembic migrations in `backend/alembic/versions/`:

- `0001_initial_schema.py` — all tables, constraints and indexes (autogenerated from the models and checked with `alembic check`).
- `0002_rls_and_storage.py` — Row Level Security, `profiles → auth.users` cascade, private storage buckets. Supabase-specific parts only run when the `auth`/`storage` schemas exist, so the same migrations run on plain Postgres in tests.

Apply with `./scripts/migrate.sh`. Never edit production tables by hand; add a migration (`alembic revision --autogenerate -m "..."`, review it, commit it).

## Tables

| Table | Purpose | Notable constraints |
|---|---|---|
| `profiles` | One row per user (id = Supabase user id) | FK to `auth.users` with cascade delete |
| `documents` | Uploaded resumes and job descriptions, extracted text and structured data | type and parsing-status checks; raw text purged after `DOCUMENT_RETENTION_DAYS` |
| `interviews` | Session configuration and state | duration ∈ {10,20,30,45}; rigor and status checks; unique `(user_id, idempotency_key)` |
| `interview_plans` | The approved plan (objectives, competency weights, questions) | unique `(interview_id, version)` |
| `questions` | Ordered planned questions | unique `(interview_id, sequence_number)`; difficulty 1–5 |
| `answer_attempts` | Every attempt, never overwritten | unique `(question_id, attempt_number)`; **partial unique index: at most one selected attempt per question** |
| `interview_events` | Ordered event log | unique `(interview_id, sequence_number)` and `(interview_id, client_event_id)` |
| `reports` | Validated evaluation | one per interview; score 0–100 check |
| `recordings` | **Primary key = user_id**, so each user has exactly one current recording | |
| `recording_uploads` | Every issued upload slot | unique path; used to verify confirmations and clean orphans |
| `feedback` | Rating 1–5 + comment | unique `(user_id, interview_id)` |
| `evaluation_jobs` | Durable report-generation queue | one per interview; lease column `locked_until` |
| `storage_cleanup_tasks` | Deferred deletions that failed | retried with backoff |
| `ai_usage` | Every AI call: provider, model, tokens, latency, success, error code | |

## Row Level Security

RLS is enabled on every table. Users (`authenticated` role) can `select` only their own rows; ownership of child rows is checked through `interviews.user_id`. There are no insert/update/delete policies: all writes go through the backend. Internal tables (`evaluation_jobs`, `recording_uploads`, `ai_usage`, `storage_cleanup_tasks`) are revoked from `anon` and `authenticated`. This is verified by `backend/tests/test_rls.py`.

The backend connects as the database owner (bypasses RLS) and enforces ownership in every query. The Supabase secret key is used only server-side for Storage.

## Connection notes

- Use the **Session pooler** connection string on Render (Render is IPv4; Supabase direct connections are IPv6).
- The engine sets `prepare_threshold=None`, so the transaction pooler (port 6543) also works.
- Each request gets its own `AsyncSession`; none is shared across requests.
